## 1. 怎么用这份报告（实施线须知）

1. **文档是唯一权威**：任何行为改动先改《需求书》/《架构书》（走变更记录），再动代码；**实现与文档不一致 = 缺陷**（双向：代码偏离文档是缺陷；文档偏离现实也要回写）。
2. **按 IM 施工、按 TC 验收**：每条 IM 有对应 RQ/AR 与验收方式；完成后在本报告状态列回填（✅ + commit 短 SHA）。
3. **防呆红线（纳入每轮代码审查清单）**：
   1. 绝不为内部原因（重载/刷新/资源回收）中止在途朗读请求（AR-§4.8.3 / ADR-009）；
   2. 绝不在已有音频时调用 `error()` 强停（AR-§4.8.6）；
   3. 绝不"假成功"（非空文本零音频以成功收尾）——但"整请求全零"必须 error 可见；
   4. 主进程零推理（AR-§1.7）；`:tts_service` 进程零 Flutter（AR-§5.1.1）；
   5. native 释放只允许在守卫锁内、无任何持有者时（ADR-008）；
   6. 微淡化（2~5ms）**仅限请求首块头部/末块尾部**，严禁下沉进 PcmChunker 分段流式路径（AR-§4.8.2 A5）；
   7. 合成线程**严禁**执行 IO、去抖或锁长等待；配置与映射预构建（AR-§4.8.4）；
   8. 存量模型回填 `.completed` 哨兵前**必须通过清单校验**，严禁坏包被标记（AR-§11.1）；
   9. SAF 离线导入**必须强制经 SafeExtractor** 解压至暂存区，严禁另写解压循环（AR-§6.5）。
4. **CI 门槛**：PR 必须绿（lint ＋ core/engine 单测 ＋ `flutter test` ＋ assembleDebug）才可合入；Release 产物挂 `gh release`（对齐仓库 GITHUB_MEMO）。
