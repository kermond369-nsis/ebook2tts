## 1. 架构总则与硬约束

1. **系统 TTS 引擎必须是原生服务**（`TextToSpeechService` 子类）：生命周期由 Android 系统与外部客户端（Legado 等）驱动，**绝不依赖 Flutter 进程存活**；
2. **合成回调只允许在系统合成线程上调用**（AOSP：All methods can be only called on the synthesis thread）；
3. **声音出口**：对系统客户端，唯一出口＝`SynthesisCallback`；**唯一豁免**＝配套 App 的预览试听/示例朗读（引擎进程内 `PreviewPlayer`，ADR-006 修订版）；引擎绝不写音频文件给用户；
4. **平台契约以 AOSP 源码为准**：`start()` 单请求 ≤1 次；成功→`done()`；失败→`error(code)`→`done()`（官方 javadoc："done has to be called if start and/or error was called"；框架存在兜底补偿，但**不得依赖**，见 AR-§4.3 注）；客户端中止→立即静默退出（`PlaybackSynthesisCallback.done()` 在 STOPPED 态安全早退，但不作为设计依赖）；`audioAvailable` 长度 `0 < len ≤ 8192B`；
5. **离线优先**：除模型下载外零网络；不打印正文到日志（隐私）；
6. **一切"完成"以真机（Legado + 系统设置）实测为准**，模拟器只做粗筛；
7. **推理唯一性（硬约束）**：sherpa/ONNX 运行时与模型**仅允许**在 `:tts_service` 进程加载与执行；主进程与 Dart 侧严禁引用推理类（防双加载内存爆炸、防击穿 NFR 预算；ISSUE-02）。

## 2. 系统总览

### 2.1 模块划分（Gradle）

```
ebook2tts-local/
├─ core/     纯 Kotlin/JVM：文本管线、音色模型、状态机核心、目录清单（可 JVM 单测，零 Android 依赖）
├─ engine/   Android Library：TTS 服务、Sherpa 后端、模型管理、配置存储(MMKV)、IPC（预览控制 AIDL、状态广播）、协议 Activities
└─ app/      Flutter 宿主：Dart UI + 原生桥（MainActivity / 下载前台服务 / 预览控制桥，零推理）
```

### 2.2 进程拓扑（ADR-001）

```
主进程 (com.mimo.ebook2tts.local)                  :tts_service 进程（纯原生 · 唯一推理进程）
┌────────────────────────────┐                    ┌──────────────────────────────────┐
│ Flutter UI (Dart)          │                    │ LocalTextToSpeechService         │
│  ├ Pigeon/MethodChannel ──▶│                    │  ├ EngineStateMachine            │
│  ├ 模型下载前台服务(FGS)    │    MMKV(多进程)     │  ├ SherpaBackend (JNI)           │
│  ├ 预览控制桥 ──(AIDL)─────▶│◀──────────────────▶│  ├ PreviewPlayer(AudioTrack+焦点) │
│  └ 协议 Activities(轻量)    │  AIDL控制/状态广播  │  ├ 广播接收: ENGINE_RELOAD        │
└────────────────────────────┘                    │  └ 状态回写+广播: ENGINE_STATUS…  │
外部客户端(Legado) ──BIND_TTS_SERVICE──▶ 系统框架 ──▶ :tts_service                    │
                                                   └──────────────────────────────────┘
```

- 预览控制 AIDL 服务声明于 `:tts_service`，`exported=false`（仅同应用）；主进程桥接绑定；
- 主进程**零推理、零模型加载**（AR-§1.7 硬约束）。

### 2.3 数据流
- **朗读**：客户端 → 系统框架 → `:tts_service` → 状态机 → 文本管线(`:core`) → Sherpa 分段推理 → PCM 分块 → `SynthesisCallback`；
- **试听/示例朗读**：Flutter UI → Pigeon → 主进程桥 → AIDL → `:tts_service` PreviewPlayer（合成+播放一体）→ 事件/进度回传 UI；
- **配置**：Flutter 写 MMKV → 定向广播（`ENGINE_RELOAD`）→ 引擎热重载（ADR-002）；
- **状态**：引擎写 `status.*`（MMKV）+ 定向广播（`ENGINE_STATUS_CHANGED`）→ 主进程读取并 EventChannel 推送；
- **模型**：主进程下载服务落盘 → `.completed` 标记 → 广播通知引擎热切换。

## 4. 引擎设计

### 4.1 引擎状态机（`:core` 纯 Kotlin）

| 状态 | 含义 | 进入条件 |
|------|------|----------|
| `NO_MODEL` | 无可用模型 | 启动检查失败 / 模型被删 |
| `INITIALIZING` | 正在加载 native | 服务创建 / 热重载触发 |
| `READY` | 空闲可合成 | 加载成功 |
| `SYNTHESIZING` | 正在流式合成 | 收到有效请求 |
| `RELOADING` | 换装中（旧已停、新加载中） | 配置/模型变更 |
| `ERROR` | 持续故障 | 加载失败且无法恢复 |

关键转换：
- `INITIALIZING --(无模型)--> NO_MODEL`：请求一律 `error(ERROR_NOT_INSTALLED_YET)`（RQ-112）；
- `READY|INITIALIZING --请求-->`：`INITIALIZING` 时**等待 ≤10s**；超时 → `error(ERROR_SYNTHESIS)`；
- `SYNTHESIZING --重载请求-->`：**不中止在途请求**；置 pending → 当前请求正常完成后、接缝窗口执行换装 → `RELOADING`（分级生效见 AR-§4.8.3 / ADR-009）；
- `* --onDestroy-->`：置关闭标志（拒绝新请求）→ `requestStop()` → `super.onDestroy()`（**仅发停止信号，非阻塞**）→ **守卫锁内等待合成线程退出（≤3s，常规 ≤数百 ms）** → 释放 native；超时则不释放、交棒合成线程 finally（`releasePending`）。**顺序不变量：native 释放只允许发生在"守卫锁内、且无任何持有者"之后**（ADR-008）。

### 4.2 线程模型与互斥（对应 R-01）

| 线程 | 职责 | 规则 |
|------|------|------|
| 系统合成线程 | 系统请求：文本管线、native 推理、回调推送 | 请求级天然串行；**守卫锁内操作 native** |
| 预览线程（预览执行器） | PreviewPlayer：试听/示例朗读的合成+播放 | 与朗读**共享同一守卫锁**串行化；排队点＝当前段结束；置停止后立即退出 |
| 重载工作线程 | 单线程 executor + **400ms 去抖**（保留 0.0.2 机制） | **接缝换装**（不中止在途请求）；「停-等-换」仅在请求接缝窗口、**守卫锁内**执行换装并释放旧 backend（AR-§4.8.3） |
| Binder 线程池 | `onStop/onGetVoices/onIsValidVoiceName/...` | **纯内存响应**：音色列表等启动时预构建、不落盘不等待 |
| Native 回调线程 | = 调用线程（sherpa 头文件：callback 在当前线程调用） | 在合成线程内同步执行；回调返回 0 即停止本次调用内剩余段 |
| 服务主线程 | 生命周期（onCreate/onDestroy）、广播收发 | onDestroy 允许**有界等待**（≤3s，见 AR-§4.1） |

**native 守卫锁（ADR-008，唯一互斥）**：持锁者才可触碰 `SherpaBackend`/native；覆盖 ①系统合成 ②预览合成 ③换装 ④销毁释放。任何超时/拿不到锁的路径**不得释放 native**。

**竞态消除（闭环 R-01 + V1"半修"补齐）**：① 去抖+串行（已有）；② 换装与合成互斥（停-等-换，锁内）；③ 旧 backend 只在守卫锁内释放；**锁被合成持有期间零释放可能**；④ **销毁竞态**：锁内等待 + 超时交棒（ADR-008）；⑤ **重载不打断连续性**：换装仅接缝窗口执行、绝无在途中止（AR-§4.8.3）；⑥ 验收＝TC-07 压测 + 会话销毁专项 + 连续性实测（AR-§10）。

### 4.3 回调契约（逐条验收）

| 时机 | 动作 | 约束 |
|------|------|------|
| 首个 PCM 块就绪 | `start(sr, PCM_16BIT, 1)` | **单请求 ≤1 次**；样本率取当前 backend（Kokoro 24k / VITS 16k）；返回非 `SUCCESS`（含 STOPPED）→ 静默退出不再推送 |
| 逐块推送 | `audioAvailable(buf, off, len)` | **`0 < len ≤ getMaxBufferSize()`（Playback 路径实证＝8192B；越界/为 0 会抛 `IllegalArgumentException`）**；返回非 SUCCESS 时停止生成并跳出 |
| 全部完成 | `done()` | 成功路径必达 |
| 失败 | `error(code)` 后接 `done()` | 官方 javadoc："has to be called if start and/or error was called"（0.0.2 此路径缺失，本版修复） |
| 非空文本零音频 | 强清洗重试 →（已部分音频）静音占位；仅整请求全零才 `error` | **禁止静默成功，也禁止中途 error 强停**（AR-§4.8.6） |
| 客户端中止 | **不调 done，立即静默退出** | 若误调 done()，STOPPED 态会安全早退（源码实证）——但不作为设计依赖 |
| 纯空文本/垃圾行 | `start()+done()` 零音频 | 让客户端正常推进 |
| 回调持有 | `onSynthesizeText` 返回后**不得再触碰 callback** | AOSP 硬性要求 |

> **注（框架兜底，实证）**：AOSP `SynthesisSpeechItem.playImpl()` 在 `onSynthesizeText` 返回后有补偿：`if (hasStarted() && !hasFinished()) done();`（TextToSpeechService.java L1035-1038，注释原文："Fix for case where client called .start() & .error(), but did not called .done()"）。即缺 done() 的常见路径被框架兜住；但该补偿不覆盖全部边界（如 start 前即失败），且是对"不合规引擎"的补丁——本引擎**必须**合规显式调用，不依赖补偿。

### 4.4 流式合成管线（ADR-003）

```
原文 → TextClean.normalize → analyzeSegments（旁白/对白单元）
     → 首段微切（见下，先发先出声）
     → 逐段：generateWithCallback（段粒度回调；返回值 0=停止 / 1=继续）
          └ float32 → PCM16 → PcmChunker（≤8192B/块，聚合 2048~4096 samples≈86~170ms）
     → 首块前 start() 一次；段间按需求插静音 PCM（基线 120ms，随语速缩放）
     → 结束 done()
```

- **sherpa 回调粒度（源码实证，修正 v0.1 表述）**：
  - Kokoro（`offline-tts-kokoro-impl.h` L308-326）：按"段"批处理（batch=1 段），**每段推理完成后整段回调一次**，无段内流式切片；回调返回 0 → 停止本次调用内**后续段**；
  - VITS（`offline-tts-vits-impl.h` L298-305）：短文本**整段一次回调**（progress=1.0）；
  - 结论：**流式粒度＝段**；TTFT 由"首段推理时长"决定 → 首段微切是 TTFT 主战术。
- **首段微切规则（v0.2 强化）**：① 首句 ≤16 字 → 整句直发；② 否则在 6~16 字区间取**最靠前**的逗号/顿号/分号/冒号之一为界（标点归首段）；③ 区间内无标点 → **硬切第 14 字**（余部顺延为下一段，不丢字）。切点参数化，真机校准；目标：首段推理 ≤~250ms @保底机型。
- **取消双保险（ISSUE-05）**：a) 外层逐段循环**每次调用前**检查停止标志，置位立即跳出；b) 回调内返回 0（停本次调用内的后续段）。`onStop` → 标志位 → 目标响应 ≤200ms（TC-02）。
- **TTFT 战术**：服务创建即预热初始化；首段微切；可选后台哑句预热（低优先级）；全程 `PERF|` 打点（TTFT/RTF，供脚本采集）；
- **替换旧的整段拼接**：不再使用"全量 ByteArray 后回放"（闭环 R-05）；`SegmentCache` 保留但需按字节上限（≤16MB）并统计命中率（`status.pcache`）。

### 4.5 音色与多角色

- **池构建**：Kokoro v1.1 zh 103 音色（sid 0–102）＋ VITS zh-ll 5 音色；命名表资产 `voice_names.json`（id↔sid↔中文名↔性别），`Voice.name`＝中文名（ADR-007），**兼容校验旧 ID**（`zm_58`/`zf_3` 等历史值仍可通过 `onIsValidVoiceName`）；

- **显式音色覆盖（DQ-7）**：默认"智能多角色"——忽略客户端自动注入的默认音色名；设置项可切"尊重阅读器"（固定单音色）；判定规则在设置文档中逐字定义；
- **会话状态（闭环 R-10/ISSUE-08）**：`knownSpeakers` 加**容量上限**（如 200）；**静默超时重置**（3~5 分钟无请求）；**特征文本重置**（"第X卷/作品信息"）；App 一键重置；单句无名对白→继承会话窗口（约 30s）或已登记对话角色轮转；
- **防御（RQ-113）**：空池/单性别池禁止取模，回退旁白。

### 4.6 文本处理管线（`:core`，纯函数）

- **章节标题**：不再当垃圾行丢弃（改为**朗读**）；正则收紧为"短标题形态"（限长度 ≤24 字、`第X[章回节卷]` 后仅允许标题文本），修复"第3节车厢"误吞（RQ-108 负例）；"第128章"→数字规范化读法；
- **标点/停顿**：基线静音表（，、：≈180ms；。；≈350ms；终止符≈500ms 属 M2 分级，接口先预留）；
- **语速与情绪（RQ-107 / ISSUE-09）**：
  - `readerSpeed = request.speechRate / 100f`（AOSP 单位：100＝正常；缺省＝框架默认 1.0×）；
  - 合成语速 `actualSpeed = clamp(readerSpeed × (1 + emotionOffset), 0.5f, 2.0f)`；**`emotionOffset ∈ [-0.10, +0.10]` 强约束**（M2 情绪模块；M1 恒 0）；**应用不做任何二次放大**；
  - 映射到 sherpa `GenerationConfig.speed`（>1 更快），逐字记录于实现；
- **广告行/平台标签**：保留现有规则；**不打印正文**；
- **NER 预留**：`SpeakerResolver` 接口（默认规则实现；M2 可插轻量模型）。

### 4.8 朗读连续性专项设计（断音/跳句治理）

> 来源：甲方指示（2026-09-13）。相关修订：ADR-009、AR-§4.1/4.2/4.3/4.7。

#### 4.8.1 框架缓冲模型（AOSP 实证，优化预算以此为准）

| 事实 | 出处（AOSP `SynthesisPlaybackQueueItem.java`） | 架构含义 |
|------|------|----------|
| 单请求"未消费音频"上限 **500ms**：超出则 `audioAvailable` 阻塞（背压） | `MAX_UNCONSUMED_AUDIO_MS=500`（L39-44；put() 阻塞条件） | 合成线程最多领先播放 ~500ms；**下一句的"免空隙合成窗口 ≤500ms"** |
| 完成回调在**整条播完**后派发（播放线程 `waitAndRelease()` 排干 → `dispatchEndStatus()`） | L114-149 | 以 onDone 驱动下一句的客户端：**句间零缓冲重叠，空隙全裸露** |
| 每条请求**独立 AudioTrack**（播放项构造即 `new BlockingAudioTrack`；stop 即硬停丢缓冲） | L90、L152-186 | 请求切换有固有开销（真机可测）；取消响应 ≤200ms 可行（TC-02） |

**句间空隙公式（分模式治理预算）**：

```
① 预排队客户端（QUEUE_ADD 前置派发）：
   句间空隙 ≈ max(0, TTFT(下一句) − 上句剩余播放窗口) ＋ 请求切换开销
   上句剩余播放窗口 ≤ min(500ms, 上句音频总长 − 上句合成耗时)；短句（几百 ms 音频）窗口等比例收缩。

② 等 onDone 客户端（收到完成回调才发下一句）：
   句间空隙 ≈ 客户端回合(onDone→下一请求) ＋ TTFT(下一句) ＋ 请求初始化开销
   注：完成回调在 waitAndRelease() 排干后派发，可用缓冲窗口恒为 0。
```

- 校准目标：预排队下 **TTFT ≤ ~350ms 级**对长句可无缝；短句边界与等 onDone 模式真机实测后回写 NFR 校准说明；
- 空隙归属三分：客户端回合 / TTFT / 请求切换与系统——用 AR-§4.8.5 打点区分，禁止拍脑袋归因。

#### 4.8.3 变更生效分级（ADR-009）

**红线：任何情况下不得为内部原因（重载/刷新/资源回收）中止在途朗读请求。**

| 级别 | 变更类型 | 生效策略 |
|------|----------|----------|
| L1 | 参数类：旁白音色、语速、角色模式、静音长度 | 无需重载；**下一请求生效**；在途请求不受影响（满足 RQ-111 ≤3s 对新请求生效） |
| L2 | 后端类：模型切换、线程数 | **接缝换装**：置 pending；当前请求**正常完成**后，在"请求接缝窗口"执行换装（停-等-换＋守卫锁）；App 显示"待生效"；warm-swap（后台加载并预热新后端 → 守卫锁内原子换指针 → 释放旧）仅高端机型 |
| L3 | 显式操作（"立即重新加载"） | 允许提示"将在当前朗读句结束后生效"；**仍不中止在途请求** |

- **生效时机（请求接缝，杜绝静默计时）**：置 pending 后不中止在途请求；在当前请求正常完成、守卫锁释放的接缝窗口执行换装（onSynthesizeText 尾部或下一请求开始前，二者等价）；换装期间到达的新请求按 `INITIALIZING` 等待规则处理（≤10s），对用户表现为自然的句间短停顿；**严禁以"≥N 秒无请求"类静默计时作为生效前提**（连续朗读中请求间隔为毫秒级，将导致永久不生效）；若朗读已暂停，pending 静默等待、恢复朗读时于接缝立即生效；
- warm-swap 适用限制：仅限**高端机型（可用 RAM ≥ 8GB）或内存实测达标者**，启用前做内存充足性判断；中低端默认**接缝冷换装**（先释放旧实例再加载新实例），杜绝双 ONNX 实例并存击穿 NFR 峰值预算；
- 变更合并（Coalescing）：pending 期间新变更覆盖旧变更（单一原子引用），执行时以最新生效值/MMKV 快照为准；收到 `onDestroy`/stop 即撤销 pending，不得在销毁中拉起新模型；
- 下载完成后的"自动热切换"同受本规约约束（默认 L2）。

#### 4.8.4 合成线程纪律（TTFT 纯净度）

1. 合成线程只做：文本管线 → 推理 → 回调推送；**禁止** IO、锁长等待、去抖、任何重活；
2. 400ms 去抖仅存在于重载线程；预览合成走独立线程但持同一守卫锁（不与系统合成线程抢跑）；
3. 换装/释放仅在请求接缝窗口执行（4.8.3），不得在请求进行中插队；
4. 每请求路径零非必需初始化（音色映射、正则、静音表启动时预构建——AR-§4.2 Binder 行）。

#### 4.8.5 连续性打点与验证（先量后治）

- **打点协议 `GAP|`**（Debug/诊断模式）：每请求记录 `req序号 | recv时刻 | 首块时刻 | synth_done时刻 | 音频总长ms | 估算客户端回合 | 段数 | sid`；
- **注意（本版修正）**：引擎侧 `callback.done()` 仅为**合成完成**（synth_done），**不是播完**；完成回调由框架在排干后才派发、引擎不可见——**禁止用 synth_done 计算客户端间隔**（高加速比下将虚增数秒）；
- **估算客户端回合** ＝ max(0, 本句 recv时刻 − (上句首块时刻 ＋ 上句音频总长ms))（估算，误差受缓冲与调度影响、±数百 ms 级，真机校准）；
- **空隙归属三判**：估算客户端回合大 → 客户端；recv→首块大 → TTFT（引擎）；两者正常仍听得到空隙 → 请求切换/系统（蓝牙、省电、其它 App）；
- **真机矩阵**：三档机 × 连续 30min × {暂停/恢复/切章/锁屏/来电}；指标：**丢句率=0、句间空隙 P50/P95、无爆音**；
- 可选：诊断模式导出单条请求 PCM 供听测定位。

#### 4.8.6 假成功禁令（防静默丢句）

- 定义：**非空文本**（管线后仍有可读内容）**整请求**零音频却以成功收尾 ＝ 假成功 ＝ 静默丢句——**禁止**；
- **单元合成零音频的降级链**：首试原样 → 失败 → ①**字符强清洗重试**（剔除非汉字/英文/数字/常用标点后重试一次；零音频的确定性根因是 tokenizer/G2P 无法映射的字符，与语速/情绪参数无关）→ ②仍失败且**本请求已有前序音频**：注入 ~150ms 静音占位（**保持段序**：占位挂起、于后续首个成功段前补推、请求尾补推余量）＋ `WARN|DROP_UNIT` 日志＋诊断计数（RQ-304 可见）；最后**正常 `done()` 收尾**；
- **严禁在已有音频时调用 `error()`**：框架会 `item.stop(statusCode)` → `mAudioTrack.stop()` 硬停并丢弃缓冲（腰斩＋爆音＋阅读中断；源码实证 L250-254 / L185）；
- **整请求 error 的唯一触发条件**：整条请求所有单元均未产出任何 1 字节音频（或清洗后全空）→ `error(ERROR_SYNTHESIS)` ＋ `done()`（可见告知）；
- 零音频成功仅限"管线判定为无内容"（真空行/纯装饰符），保持 `start()+done()`。

### 5.1 `:tts_service` 边界
- 声明：`android:process=":tts_service"`（service 本体；协议 Activities 留主进程、轻量实现、不拉起 Flutter；预览 AIDL 服务声明于 `:tts_service`、`exported=false`）；
- 启动：系统/客户端 bind 或 start；**不主动常驻、不滥用前台**；
- 销毁顺序：见 AR-§4.1 / ADR-008（守卫锁内释放，超时交棒）。

### 5.1.1 多进程 Application 初始化约束（ISSUE-03，防呆）
- `Application` **必须继承 `android.app.Application`**（严禁 `FlutterApplication` 或任何在 `onCreate` 无条件初始化 Flutter 的基类）；
- `onCreate()` 内先判定当前进程名：API 28+ 用 `Application.getProcessName()`；**API 27 兜底读 `/proc/self/cmdline`**；
- 进程名＝`:tts_service`：**仅**初始化 MMKV（多进程模式）、日志、崩溃捕获、迁移检查（AR-§11.1）；**严禁**触碰 Flutter Engine / 插件 / UI 组件；
- 仅主进程：初始化 Flutter Engine 与 Pigeon 注册。
- **防呆**：engine 模块推理入口加 `ProcessGuard.assertEngineProcess()` 运行时断言（非引擎进程调用直接抛错）；引擎进程冷启 ≤1.5s（NFR，真机校准）。

### 5.2 配置键规范（MMKV，多进程模式）

### 5.3 状态回传（ISSUE-04 修订）
- 引擎写：`status.state` / `status.modelId` / `status.lastError` / `status.pcache` 到 MMKV，**并发送定向广播 `ENGINE_STATUS_CHANGED`**（MMKV 无跨进程变更监听——源码/官方语义，必须靠广播补通知）；

### 6.2 模型清单（远程可更新 + 内置兜底）
- **清单结构（v0.4 实施回写，以代码为准）**：仓库根 `manifest.json`（`schema=1`）：
  `{schema, version, updatedAt, models:[{id, label, desc, archive, url, mirrors[], sha256, downloadBytes, extractedBytes, files{kind,model,voices,lexicon,dataDir,ruleFsts,tokens}, recommended|highEndOnly|lowEndDefault}]}`；
- **取用顺序**：远程（官方 `raw.githubusercontent` → **国内加速前缀**逐个尝试）→ 本地缓存（6h TTL，写盘前必须过校验）→ **内置兜底**（`core/ModelCatalog` 编译期常量）；**任一字段不合法整份作废**（schema/version>0/https-only/sha256 64hex/体积 `(0,8GiB]`/id 非空且唯一），绝不部分采纳；**版本下限＝内置清单版本**（拒绝回滚投毒）；
- **下载源**：`url`＝官方主源，`mirrors[]`＝镜像/加速源；**多源并行测速**（64KB `Range` 探测，取字节/ms 最高）选优、失败按序回退。实测口径（2026-09-14）：GitHub 官方源国内直连**不可达**（`ConnectException …:443`，ICMP 通≠TCP 通）；**HF 类镜像不适用**（HF 仓库存解压后散文件、**不提供 `.tar.bz2` 归档**，按归档路径必然 404）；国内可用的是 GitHub 加速前缀（实测 `ghfast.top` 216–358 KB/s、`hk.gh-proxy.com`、`ghproxy.net`，均返回 `Content-Range` 支持续传）。**加速前缀会漂移**（同日 6 选 4 失效）⇒ 必须靠清单远程可更新 + 多源测速容灾，**每次换源须附实测证据**；
- **自定义镜像（用户可填）**：支持 **基址**（目录前缀，自动拼归档名）或**下载加速直链**（完整 URL，原样使用）；**仅 https**（应用 `usesCleartextTraffic=false`，明文必被系统拒绝）；
- **防漂移**：仓库根 `manifest.json` ⟷ 内置兜底 `ModelCatalog` 由单测逐字段断言一致（`ManifestCodecTest.rootManifest_matchesBuiltin`）。
- **模型矩阵（RQ-203 补齐）**：`kokoro-int8`（主推、首次引导默认下载）、`vits-zh-ll`（保底档＝本地合成下限机型默认推荐）、`kokoro-fp32`（高端可选）；三者均**不内置**、走下载流程；体积/文件数以清单实测值为准。

### 6.3 下载服务（主进程 FGS）
- 流程（v0.4 实施回写）：**多源并行测速** → 磁盘预检（≥2.5× **清单实测**解压体积）→ 断点续传（`.part`；服务器不支持 `Range` 则**整包重下**，绝不半包拼接；**残包超长时清空重下**避免 416 死循环）→ **下载体积与清单声明对账** → SHA-256 校验 → **安全解压（§6.5）** → **解析模型根**（官方归档顶层带目录名，须上提为 §6.1 的扁平布局）→ 原子重命名 + `.completed` → 通知引擎热切换；
- 线程纪律：清单解析含网络，**严禁在主线程**；FGS 通知先以通用文案唤醒后，全部 I/O 在工作线程执行；
- 失败：残包清理、指数退避重试（≤3）、"去浏览器手动下载"兜底提示；
- 合规：`dataSync` 类型 + `FOREGROUND_SERVICE`/`FOREGROUND_SERVICE_DATA_SYNC` 权限 + Android 13+ 通知权限（RQ-201）。

### 6.4 离线导入（SAF）
`ACTION_OPEN_DOCUMENT` 选包 → ContentResolver 流式解压至 staging（**走 §6.5 安全解压器**）→ 同上校验归档（RQ-204）。

### 6.5 安全解压规约（SafeExtractor；ISSUE-06；对 §6.3 / §6.4 两类入口统一强制）
1. **路径穿越防御（Zip Slip / CWE-22）**：每个条目 `entryFile.canonicalPath.startsWith(stagingDir.canonicalPath)` 校验，违者立即终止 + 清理 + 报错；拒绝绝对路径、`..` 段、符号链接/非普通文件条目；
2. **解压体积防线**：单条目与累积解压字节数不得超过清单声明 `extractedBytes` 的 1.1 倍（且设绝对上限）；超限立即中止并清理残包；
3. **条目数上限**（防海量小文件攻击）；
4. **白名单归档**：解压产物必须与清单声明的文件集合一致（多出/缺失即拒绝）；
5. **隔离区**：一律解压到专用 `models-staging/<id>.tmp/`，绝不直接落 `models/` 或应用数据根；
6. 出处：Google Play《Zip Path Traversal》缓解要求、CWE-22；测试用恶意样本见 AR-§10。

## 14. 【P7 增补】运行模式、性能分级与后端生命周期（v0.6 / v0.7）

### 14.1 双后端等价与模式选择（对齐需求书 RQ-513~514、DQ-12）
- **架构定性**：在线后端与本地后端是**等价的两条运行路径**，不存在"主/备"关系；优先关系由用户在首次进入时选择
  （「仅在线 / 仅本地 / 谁优先」）。**App 不预置任何模型**（体积策略，与 ABI 收敛并列）。
- **决策**：新增 **ADR-016 —— 运行模式选择与"等价双后端"**：模式选择落在 UI 首启流程；选择结果持久化于配置；
  两条路径共享同一 `SynthesisCoordinator` 抽象（请求入口/中止语义/错误码统一），差异只在"合成器实现"。

### 14.2 设备性能分级与低配警告（对齐需求书 RQ-515~516）
- **决策**：新增 **ADR-017 —— 低配设备本地模式警告**：
  - **判定机制：已取消（2026-09-21 甲方二选一裁定）** —— **不写机型判定**：无型号阈值表、无玄戒例外、无运行时微基准兜底；改为 **RQ-515「无条件告知」**：进入本地模式即弹最低要求告知（文案随 RQ-519），**不判定、不限制**，用户确认后即可用；
  - **算力口径（RQ-519，2026-09-21 甲方口径）**：该阈值即**本地合成的机型下限**（本地＝骁龙 8 Gen 1+／天玑 9300+；`+` 表示**该型号及其之后发布的旗舰**，非单一型号「8+ Gen 1」）；**在线合成不设算力下限**；低于下限机型**不受任何限制**（RQ-515 改为无条件告知；性能不作承诺，见 RQ-516），且**不得**再以「天玑 1000 级／骁龙 765G 级」作为本地保底档表述；
  - ~~**例外**：小米 玄戒 O1 / 玄戒 O3 不告警~~ ⇒ **作废**（判定取消 ⇒ 无例外：**所有机型一律弹同一份告知**）；
  - ~~**兜底**：运行时微基准（一次性、离线、数秒内完成），避免仅靠型号串在定制 ROM / 新芯片上误判~~ ⇒ **作废**（判定机制已取消）；
  - ~~型号表须可随版本迭代（新型号不得一律判为低配）~~ ⇒ **作废**（无型号表 ⇒ 无「新型号误判」问题）；
  - **不阻塞主流程**：告知为提示性弹窗（**不判定、不限制**），用户确认后即可使用本地模式；低于下限机型上本地不可用/延迟极大属**可接受结果**（RQ-516）。

### 14.3 后端生命周期与就绪语义（P7 实施，对应 BUG-P7-011/013/014/015）
- **单一常驻后端**：进程内**唯一** `SynthesisCoordinator`（进程级单例），预览通道**借用**而非自建后端（`borrowed` 语义，借用方不得释放）；
- **中止唤醒**：`requestStop()` 必须 `signalReady()` 唤醒等待就绪的线程；等待按 ≤50 ms 粒度轮询，保证中止可被及时感知；
- **就绪预算**：`READY_WAIT_MS = 15_000`（真机冷加载 12 s 实测得出；常态由服务启动预热覆盖，该值仅兜底）；
- **配置变更短路**：`reloadInternal()` 以"硬指纹（modelId+线程数）/软指纹（旁白+角色模式）"分级判定，未变则跳过，
  消除"任意配置广播 ⇒ 整模型重载"的风暴；
- **错误码**：系统通道一律使用平台常量（`android.speech.tts.TextToSpeech.ERROR_*`），禁止自造常量镜像。

### 14.4 体积、ABI 与签名策略
- **ABI 收敛**：正式 `arm64-v8a`；debug 另含 `x86_64`；并以 `packaging.jniLibs.excludes` 排除 `lib/armeabi-v7a/**`（仅改 `abiFilters` 会残留）；
- **不预置模型**（RQ-513）+ **不保留备份**（`allowBackup=false`、`dataExtractionRules`/`fullBackupContent` 全排除）；
- **发布签名**：自签名密钥库（RSA 4096，有效期至 2056-09）；构建期凭据 `key.properties` 不入库；缺失时回退调试密钥（保证他人可构建）。
  签名**仅影响更新连续性**，不影响 R8/包体：release 实测 debug 1.5 G → release 398 M。

## 15. 【P7 增补】推理线程数按核簇拓扑分配（ADR-018，v0.8）

### 15.1 背景：两处实测结论冲突（不可一刀切）
| 来源 | 设备 | 实测 | 结论 |
|---|---|---|---|
| **IM-522**（P6，已批准） | 6 核**同构**设备 | 线程 2→5：RTF **1.60 → 1.37~1.42** | 线程增加 ⇒ 更快 |
| **E3**（P7，2026-09-16） | Mi MIX 2S / SDM845 = **4×A75 + 4×A55**（big.LITTLE） | 线程 7→4→2：合成 **108 s → 83.6 s → 69 s** | 线程增加 ⇒ **更慢** |

**机理**：`cores-1` 在异构核上会让 ORT 起过多线程争抢少数大核，并把工作迁到 1.76 GHz 小核，
叠加内存带宽争用 ⇒ **过度订阅**；而在同构核上，线程数≈真实并行度，仍然越快越好。

### 15.2 决策（ADR-018）
1. **自动线程数上限 = 性能核（大核）数量**：`clamp(min(perfCores, cores-1), MIN, MAX)`；
   `perfCores` 由各核 `cpufreq/cpuinfo_max_freq` **分簇判定**（行业通行做法），**严禁按 SoC 型号硬编码/白名单**；
2. **用户显式设置（`engine.threads`）仍优先**，允许覆盖至 `MAX=8`（保留 IM-522 的可用空间）；
3. **`MIN=2` 不变**；上限不再是无条件 `cores-1`；
4. 本次为**修正**而非推翻：IM-522 的结论在其适用域（同构核）继续成立，ADR-018 补充"异构核"分支。

### 15.3 验证要求（跨设备，不接受单机结论）
- 模拟器（x86_64，同构）与真机（SDM845，异构）**双环境**跑同一 A/B（2 / 4 / 大核数 / 原值四档）；
- 数字必须能同时解释"**同构核加线程更快、异构核超大核数更慢**"；只在一台机器上过不算过；
- 对照口径：同文本、同音色、同模型、每次冷启后单次试听，取 `PREVIEW|synth` 与 `segments_done|total_ms`。

## 16. 【P7 第二批】合成结果缓存（ADR-019，v0.9）

### 16.1 背景（实测驱动）
- 真机（SDM845）本地合成为 **69~85 s/句**（RTF 12~19×），而**重复朗读同一句**（试听连点、回听上一句、卡片重播）
  会**重复付出**同等代价；
- 语音数据是**确定性**的：同一 `(模型版本, 文本, 音色 speakerId, 语速, 采样率)` ⇒ 同一 PCM 结果。

### 16.2 决策（ADR-019）
1. **缓存键**：`modelId | speakerId | speed(规范化到 0.01) | textHash(SHA-256)`；**不含**任何可变展示态；
2. **存储**：进程内 **LRU 内存缓存**（上限按字节计，默认 **32 MB**，可配置）；**不做磁盘缓存**
   （模型文件与用户数据的落盘策略另议，避免隐私面扩大）；
3. **失效**：模型切换/音色池重建/语速变更/服务 `releaseIfIdle` 释放后端时**整体失效**（与 native 生命周期绑定）；
4. **命中路径**：`generatePcm` 前查缓存；命中 ⇒ 直接返回 PCM（跳过 native 调用），并**不改变**外部行为
   （回调时序、分段、微淡化规则一律不变——红线 3/6 不得因缓存被绕过）；
5. **可观测**：日志新增 `CACHE|hit|key=…|bytes=…` / `CACHE|miss|…` / `CACHE|evict|…`，便于复核命中率。

### 16.3 验收
- 同一句第二次合成 **耗时 ≤ 首次的 5%**（预期毫秒级）；
- `:core` 单测覆盖：命中/未命中/键差异（文本、音色、语速、模型各变动一次）/LRU 淘汰；
- 真机复验：连续两次试听同文本，第二次命中缓存（日志打点 + 耗时对照）；
- **不改变**输出音频：命中返回的 PCM 与首次逐字节一致（单测断言）。

## 17. 【P7 第二批】朗读路由模式（ADR-020，v0.10）

### 17.1 背景
产品开局**不预置模型**，由用户选择「在线模式 / 本地模式」再选「仅 X / 谁优先」（RQ-513）；
且本地与在线**等价**（RQ-514），**不得**把本地当兜底。

### 17.2 决策（ADR-020）
1. 引入**四态路由枚举**（纯逻辑，`:core`）：`only_online` / `only_local` / `prefer_online` / `prefer_local`，
   并给出互逆的**归约/反解**（两步选择 ↔ 模式），供引擎与界面共用；**判定口径不得在界面侧复刻**。
2. **硬约束**（由枚举自带语义保证）：
   - `only_local` ⇒ **不触网**（不允许在线）；
   - `only_online` ⇒ 在线不可用时**不得回落本地**：选择器返回带专用前缀的阻断结果，
     由调用点**如实报错**（系统 TTS 通道：`error()`＋`done()`＋错误结果；试听：中止并记日志）；
   - `prefer_*` ⇒ 允许回落，回落必须在日志中可见（`ONLINE|fallback=local|reason=…`）。
3. **兼容**：选择器与配置读取均带默认值 ⇒ **既有调用点零行为变化**（默认仍为 `prefer_online`）。
4. **持久化**：配置键 `route.mode`（四态）与 `route.chosen`（是否已完成开局选择）；后者驱动首启闸门。
5. **首启流程**：未选择过 ⇒ 先走两步选择页（含 RQ-515 性能提示，弹窗给「仍选本地」，**决定权在用户**）；
   已选择 ⇒ 直接进入主界面；桥不可用 ⇒ **fail-open**（视为已选择，不打断用户）。

### 17.3 验收
- 单测覆盖：解析容错、两步归约与反解互逆、四条硬约束（不触网 / 不回落 / 允许回落 / 兼容默认）；
- 真机验收（已通过部分）：首启页与两步流程、RQ-515 弹窗文案与判定依据、落库（`prefer_local`）、
  重启持久化、设置页回显与更改、在线端到端（选在线后走在线链路且开始播放）。
